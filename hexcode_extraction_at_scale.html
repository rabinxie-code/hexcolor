5B 图片 / 100B 区域
Hexcode 提取方案

面向自然图像与设计图像的超大规模颜色抽取。目标不是给每个区域运行一次通用聚类，而是将任务改写为： 每张图只解码一次、每个像素只流式访问一次、每个区域按复杂度路由到最便宜的提取器。

Primary recommendation

不要对 100B 个区域逐个运行 K-Means。

生产方案应采用“区域标签图 + 单次像素扫描 + 批内局部直方图/重频候选 + 少量 fallback”。 若区域 Mask 已经存在，Hex 提取本身可以接近 I/O / 内存带宽受限；若 Mask 不存在，语义分割将成为主要成本。

Executive summary

四个最重要的决策

这些决策对成本的影响远大于选择 OpenCV 还是 scikit-image。

01

分割与颜色抽取解耦

如果已有 layer mask、label map 或 RLE，直接复用。不要为了提取颜色再运行 SAM 或 SLIC。需要语义区域时，将分割作为独立预算。

02

按区域复杂度自适应

平坦设计区域用 exact mode；轻纹理用 robust medoid；自然纹理用固定 LUT 的 top-k palette；渐变输出 stops，而不是强压成一个 Hex。

03

批内聚合，不做区域循环

把 image pixels 与 region labels 展平，在 GPU 上进行 segmented statistics / histogram。Python 只负责调度批次，不负责 100B 次函数调用。

04

存 RGB24，不存字符串

#RRGGBB 只是展示格式。生产数据存 uint32 rgb24、method、confidence 与可选 top-k，读取时再格式化为 Hex。

关键规模变量不是“区域数”本身，而是区域像素总量。 如果区域互不重叠，成本约等于全图像素数；如果是重叠图层，成本应乘以 coverage multiplier = Σ(mask area) / image area。下面的计算器已把该变量纳入。
System architecture

推荐生产流水线

优先把小文件 I/O、解码、颜色管理、区域聚合和结果写出做成一个流水式 DAG，避免中间 RGB 落盘。

Stage 0

Source-aware parser

SVG / PSD / 设计 JSON 直接读取 fill、stroke、gradient、alpha。

Stage 1

Sequential shard reader

将大量小文件打包为顺序 shard，降低对象存储 GET 与 metadata 开销。

Stage 2

Decode once

JPEG/PNG/WebP 批量解码；处理 EXIF orientation、alpha 与异常格式。

Stage 3

sRGB normalization

Hex 按 sRGB 输出。仅非 sRGB / CMYK 数据走 ICC 慢路径。

Stage 4

Region interior

加载 label map / RLE，移除边界抗锯齿像素，生成全局 region id。

Stage 5

Stats + router

一次扫描统计 count、sum、variance、top-bin、sample 与 alpha。

Stage 6

Columnar writer

按 image row 写 nested region arrays，或按 shard 写扁平 Parquet。

Adaptive Hex v1

面向 100B 区域的算法设计

先用廉价统计判断区域类型，只把少量复杂区域送入更贵的方法。所有阈值都应在你们的真实数据上校准。

源格式优先

能拿到 SVG、PSD、HTML/CSS 或设计 JSON 时，直接读取 fill / stroke / opacity / gradient stops。该结果比从渲染像素反推更准确也更快。

统一为 sRGB 与可复现坐标

处理 EXIF orientation；常见 sRGB/untagged 图走 fast path，只有带非 sRGB ICC、CMYK 或 wide-gamut 的数据才做完整色彩变换。

生成 interior pixels

对 dense label map，可用“标签等于上下左右邻居”近似 1px 腐蚀；小区域不足时回退到原 mask，避免完全被腐蚀掉。

第一遍区域统计与固定采样

聚合 area、RGB sum/sumsq、alpha、粗量化 top-bin；每个区域用 hash-based deterministic sampling 采 32–64 个 interior pixels。

路由到最便宜的方法

Flat → exact heavy hitter；mild → sample medoid；textured → 12/15-bit LUT palette；gradient → 坐标-颜色回归与 2–5 个 stops。

输出方法与置信度

除 rgb24 外保存 method enum、top1 ratio、color spread、border removed ratio、alpha mode 与 confidence，方便下游筛选。

    rgb, alpha = decode_to_srgb(batch)       # decode once
    labels = load_region_labels(batch)       # dense/RLE

    stats, samples = segmented_first_pass(

    )

    route = classify_region_complexity(stats, samples)

    out_flat = exact_heavy_hitter(rgb, labels, route.flat)
    out_mild = sample_lab_medoid(samples, route.mild)
    out_tex  = lut_palette_topk(rgb, labels, route.textured, k=3)
    out_grad = fit_gradient_stops(samples, route.gradient)

    rows = merge_and_score(stats, out_flat, out_mild, out_tex, out_grad)
    write_nested_parquet(rows)             # no JSON strings

Image-aware policy

设计图与自然图必须分支

“一个区域对应一个 Hex”对设计元素通常合理，对自然物体通常只是人为摘要。

设计图像 / UI / 海报

  • 优先解析结构化源文件，保留 fill、stroke、gradient、blend mode 与 opacity。
  • Raster 设计图使用 interior exact mode，边界抗锯齿像素不参与主色。
  • winning coarse bin 可做第二遍 exact RGB heavy-hitter，恢复原始 24-bit 颜色。
  • 半透明元素同时保存 source RGBA 与 composited observed RGB；只有截图时不能唯一反解 source color。
  • 评价指标以 exact recovery rate、抗 JPEG/resize 稳定性和作者色偏差为主。

自然图像 / 摄影 / 纹理区域

  • 不要把光照、阴影与反射混成一个平均色；默认输出 primary medoid + top-3 palette。
  • 代表色优先选择真实出现过的样本 medoid，而不是可能不存在的 K-Means center。
  • 只在 sampled pixels 上进行 Lab/Oklab 计算，不要对所有 5e15 级像素全量做复杂色差运算。
  • 可同时保存 observed color 与去除亮度极端值后的 base-color proxy，但字段语义必须明确。
  • 评价指标以 ΔE、palette coverage、跨压缩稳定性和人工偏好为主。
GPU implementation

Kernel 级别的关键细节

一个能运行的 CuPy 原型不等于一个能稳定处理 5B 图片的生产实现。

A

批内 compact region id

每批把 region id 映射到连续的 0…R−1。不能把全球 region id 直接传给 bincount，否则输出数组会按最大 id 膨胀。

B

Shared-memory 局部直方图

生产实现应按 tile / region group 做 block-local histogram 或 heavy-hitter，再合并到全局，降低热门 bin 的 atomic contention。

C

避免全局 32K bins × regions

12-bit 的 4096 bins 可作为通用批内基线；15-bit 只用于小批或第二阶段。跨全数据集只保存 top-k，不保存完整 histogram。

D

固定 LUT 替代最近邻搜索

预先将 12/15-bit RGB key 映射到感知 palette id；运行时每像素仅需位运算与一次 LUT load，无需在线 K-Means 或 FAISS。

E

确定性与可重跑

采样位置由 image_id、region_id 与版本 seed 决定。浮点归约需定义可接受的 determinism；最终 RGB24 尽量由整数统计决定。

F

端到端融合

decode → color convert → interior check → stats 尽量保持在 GPU / pinned pipeline；不要频繁 CPU↔GPU 往返或写出中间 RGB。

一个实用的分阶段实现：先用 CuPy/Kornia 验证正确性，再用 Triton 写 fused prototype，最后将热点路径迁移到 CUDA C++ + CUB 的 BlockHistogram / Reduce primitives。这样能兼顾迭代速度和最终吞吐。

Data contract

输出格式与存储设计

100B region rows 的逻辑规模很大，但颜色字段本身很小。真正的问题是行数、重复 image_id、文件数量与读取局部性。

推荐：一行一张图，区域为 nested arrays

将行数从 100B 降到 5B，避免重复保存 image_id，并让同一图片的区域保持局部性。

RGB

Hex 延迟格式化

rgb24 = (R<<16)|(G<<8)|B。只有在 UI、日志或导出 CSV 时生成 #RRGGBB 字符串。

IO

低基数 partition

按 dataset version、source、hash prefix 或原始 shard 分区。不要为每张图、每个日期或每种颜色创建目录。

V

版本与幂等

保存 algorithm_version、LUT checksum、sampling seed 与 source checksum；重跑同一 shard 应覆盖或原子提交同一输出。

Validation plan

Benchmark 与上线计划

先证明颜色质量，再证明 kernel，再证明端到端 shard throughput。不要用单张 224×224 图的 microbenchmark 推断生产成本。

PHASE 01

Gold reference

抽取 100K–1M 图片；用 scikit-image / OpenCV / libimagequant 建立慢但可信的 CPU reference，并构造带已知 fill 的合成 SVG benchmark。

PHASE 02

GPU prototype

CuPy/Kornia 实现 batch-local q12 histogram、64-sample medoid 与 gradient detector；测量质量与显存。

PHASE 03

Fused kernel

Triton 或 CUDA/CUB 融合 interior、sampling、stats 与 top-k；在真实 shard 上测 sustained Gpixel/s 和 GPU utilization。

PHASE 04

1B-region pilot

执行约 1B 区域的灰度发布，验证失败重试、输出一致性、长尾格式、成本与下游可用性后再扩大。

质量指标

  • 结构化设计：作者色 exact match rate、gradient stops recovery、alpha recovery。
  • Raster 设计：抗锯齿边界移除后 exact/ΔE00、JPEG quality 与 resize 稳定性。
  • 自然图像：primary medoid ΔE、top-3 palette coverage、人工 preference。
  • 路由准确性：flat / texture / gradient 误分率与 fallback 比例。
  • 可复现性：同版本跨重跑、跨 worker、跨 GPU 的 rgb24 一致率。

系统指标

  • 端到端 images/s、regions/s、effective Gpixel/s，而非仅 kernel latency。
  • 对象存储 GET/s、compressed GB/s、decode utilization、GPU idle ratio。
  • 每 1B regions 的 worker-hours、失败重试比例与输出 TB。
  • P50/P95/P99 图像处理时延，按格式、分辨率、region count 分桶。
  • 坏图、超大图、CMYK、wide-gamut、透明 PNG 与重叠 mask 的长尾占比。

建议的第一版默认参数

  • 每区域 deterministic interior sample：64 pixels；小区域使用全部像素。
  • 通用 coarse palette：q12（4 bits/channel，4096 bins）。
  • Flat 区域：top1 coarse ratio + sampled color spread 双条件。
  • 自然图：primary medoid + 3-color palette；比例量化为 uint16。
  • 边界：1px label-neighbor interior；低于最小核心面积时取消腐蚀。

必须避免的坑

  • 对 100B regions 启动 100B 次 Python 函数或 GPU kernel。
  • 将 global region id 作为 bincount index，意外申请超大数组。
  • 对全部像素执行 CIEDE2000 / K-Means，而不是仅对 sampled fallback。
  • 忽略 ICC / CMYK / alpha，却把输出称为“原始设计色”。
  • 以 JSONL 保存 Hex 字符串，导致不必要的体积与解析成本。
  • 把 SAM/SLIC 的成本算进“颜色抽取”却没有单独测量。
